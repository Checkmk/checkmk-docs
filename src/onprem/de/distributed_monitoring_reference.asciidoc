[#intro]
== Einleitung

Die Einrichtung eines verteilten Monitorings führt neue Objektzustände ein.
Zusätzliche Komponenten bedeuten zusätzliche Pfade für Konfigurations- und Logdateien.
Dieser Artikel dient als zentrale Referenz für all diese für das verteilte Monitoring spezifischen Dinge.


[#connection_states]
== Verbindungszustände

In der Übersichtsseite [.guihint]#Distributed monitoring# sehen Sie in der Spalte [.guihint]#Status# den Zustand der Livestatus-Verbindung zur jeweiligen Instanz.
Folgende Werte sind möglich:
// ES: Falls du Kapazität hast, erstell bitte die pills in CSS, analog zu den Status-Darstellungen.
// ES: In assets/css/addons.css:1271 findest du jede Menge Definitionen, an die du das anlehnen kannst.

[cols="25,75"]
|===
|icon:icon_status_label_online[width=80px] |Die Instanz ist per Livestatus erreichbar.
|icon:icon_status_label_dead[width=80px] |Die Instanz ist gerade nicht erreichbar.
Livestatus-Anfragen laufen in einen _Timeout_.
Dies verzögert den Seitenaufbau.
Statusdaten dieser Instanz sind in der GUI nicht sichtbar.
|icon:icon_status_label_down[width=80px] |Die Instanz ist gerade nicht erreichbar, aber das ist aufgrund der Einrichtung eines Status-Hosts oder durch den xref:distributed_monitoring_performance#livestatusproxy[Livestatus-Proxy] bekannt.
Die Nichterreichbarkeit führt *nicht* zu Timeouts.
Statusdaten dieser Instanz sind in der GUI nicht sichtbar.
|icon:icon_status_label_disabled[width=80px] |Die Livestatus-Verbindung zu dieser Instanz ist vorübergehend durch den Administrator (der Zentralinstanz) deaktiviert worden.
Die Einstellung entspricht der Checkbox [.guihint]#Temporarily disable this connection# in der Einstellung dieser Verbindung.
|===


[#connection_state_status_host]
=== Bei Verwendung eines Status-Hosts

Bei Verwendung eines Status-Hosts gibt es weitere mögliche Zustände für Verbindungen:

[cols="25,75"]
|===
|icon:pill_site_status_unreach[width=70px] |Der Rechner, auf dem die Remote-Instanz läuft, ist für das Monitoring gerade nicht erreichbar, weil ein Router dazwischen nicht korrekt arbeitet (Status-Host hat den Zustand {UNREACH}).
|icon:pill_site_status_waiting[width=70px] |Der Status-Host, der die Verbindung zur Remote-Instanz überwacht, wurde noch nicht vom Monitoring geprüft (steht noch auf {PEND}).
|icon:pill_site_status_unknown[width=70px] |Der Zustand des Status-Hosts hat einen unbekannten oder ungültigen Wert -- dieser Zustand sollte nie auftreten.
|===


[#replication_states]
== Replikationszustände

Auf der Seite [.guihint]#Setup > Activate pending changes# sind im verteilten Monitoring mit zentralem Setup zusätzliche Symbole für den Replikationsstatus der Remote-Instanzen verfügbar.
Folgende Symbole zeigen Ihnen den Replikationsstatus der Konfigurationsumgebung:

[cols="25,75"]
|===
|icon:icon_need_restart[] |Diese Instanz hat ausstehende Änderungen und muss neu gestartet werden.
Mit einem Klick auf den Knopf icon:icon_need_restart[] können Sie dies gezielt für diese Instanz durchführen.
|icon:icon_need_replicate[] |Die Konfigurationsumgebung dieser Instanz ist nicht synchron und muss übertragen werden.
Danach ist dann natürlich auch ein Neustart notwendig, um die Konfiguration zu aktivieren.
Beides zusammen erreichen Sie mit einem Klick auf den Knopf icon:icon_need_replicate[].
|===

[#directories]
=== Verzeichnisse

[cols="44,~"]
|===
|Pfad |Bedeutung

|`~/etc/check_mk/conf.d/` |Konfiguration von Hosts und Regeln für {CMK}. Legen Sie hier Konfigurationsdateien ab, die per xref:distributed_monitoring_constrained#cmcdump[CMCDump] erzeugt wurden.
// MFS: Niemanden auf dumme Gedanken bringen...
// Nur das Unterverzeichnis `wato/` wird in der Konfigurationsumgebung verwaltet und ist dort sichtbar.
|`~/etc/nagios/conf.d/` |Ablageort für selbst erstellte Nagios-Konfigurationsdateien mit Hosts und Services. Dies wird beim Einsatz von xref:distributed_monitoring_constrained#livedump[Livedump] auf der Zentralinstanz benötigt.
|`~/var/check_mk/autochecks/` | In diesem Verzeichnis legt die Service-Erkennung gefundene Services ab. Die Speicherung erfolgt immer lokal auf der Remote-Instanz.
// MFS: Das hat nicht speziell mit verteiltem Monitoring zu tun.
// |`~/var/check_mk/rrds/` |Ablage der Round-Robin-Datenbanken für die Archivierung der Messwerte beim Einsatz des {CMK}-RRD-Formats (Default bei den kommerziellen Editionen).
// |`~/var/pnp4nagios/perfdata/` |Ablage der Round-Robin-Datenbanken bei PNP4Nagios-Format ({RE}).
|===


[#log_files]
=== Log-Dateien

[cols="44,~"]
|===
|Pfad |Bedeutung

|`~/var/log/liveproxyd.log` |Log-Datei des xref:distributed_monitoring_performance#livestatusproxy[Livestatus-Proxys].
|`~/var/log/liveproxyd.state` |Aktueller Zustand des Livestatus-Proxys in lesbarer Form. Diese Datei wird alle fünf Sekunden aktualisiert.
|`~/var/log/notify.log` |Log-Datei des {CMK}-Benachrichtigungssystems.
|`~/var/log/mknotifyd.log` |Log-Datei des xref:distributed_monitoring_notifications#centralized_notifications[Benachrichtigungs-Spoolers].
|`~/var/log/mknotifyd.state` |Aktueller Zustand des Benachrichtigungs-Spoolers in lesbarer Form.
Diese Datei wird alle 20 Sekunden aktualisiert.
|===


[#configuration_files]
=== Konfigurationsdateien

Nehmen Sie keine Änderungen an Konfigurationsdateien vor, wenn Sie dazu nicht explizit -- zum Beispiel von einer Support-Person -- aufgefordert wurden.
Erstellen Sie _vor_ möglichen Änderungen immer Backups.

[cols="44,~"]
|===
|Pfad |Bedeutung

|`~/etc/check_mk/multisite.d/sites.mk` |Hier speichert {CMK} die Konfiguration der Verbindungen zu den einzelnen Instanzen.
// MFS: Hier wohnen fette Drachen
// Sollte aufgrund von Fehlkonfiguration die Oberfläche so „hängen“, dass sie nicht mehr bedienbar ist, können Sie die störenden Einträge direkt in dieser Datei editieren.
// Falls der Livestatus-Proxy zum Einsatz kommt, ist anschließend jedoch ein Editieren und Speichern mindestens einer Verbindung notwendig, da erst hierbei für diesen Daemon eine passende Konfiguration erzeugt wird.
|`~/etc/check_mk/liveproxyd.mk` | Diese Datei enthält die Konfiguration für den xref:distributed_monitoring_performance#livestatusproxy[Livestatus-Proxy]. Sie wird von {CMK} bei jeder Änderung an der Konfiguration des verteilten Monitorings neu generiert.
|`~/etc/check_mk/mknotifyd.d/wato/global.mk` | Diese Datei enthält die Konfiguration für den xref:distributed_monitoring_notifications#centralized_notifications[Benachrichtigungs-Spooler]. Sie wird von {CMK} beim Speichern der globalen Einstellungen erzeugt.
|`~/etc/check_mk/conf.d/distributed_wato.mk` | Diese Datei stellt auf den Remote-Instanzen sicher, dass diese nur ihre eigenen Hosts überwachen.
// MFS: Das macht man heutzutage über die Global settings.
// |`~/etc/mk-livestatus/nagios.cfg` |Konfiguration von Livestatus bei Verwendung von Nagios als Kern. Hier können Sie die maximale gleichzeitige Anzahl von Verbindungen konfigurieren.
|===
