[#intro]
== Einleitung

Die eingebaute Benutzerverwaltung von {CMK} gibt Ihnen Kontrolle darüber, wer in welchem Umfang auf welche Bereiche Ihrer Monitoring-Umgebung zugreifen darf.
In größeren Organisationen kann es wünschenswert sein, ein schon bestehendes System zum Identitätsmanagement an {CMK} anzubinden.
Die Benutzer, die sich in der Weboberfläche von {CMK} einloggen können, werden dann über einen externen Dienst zentral verwaltet.
Welche Möglichkeiten es dafür gibt, erfahren Sie in diesem Artikel.

Beim Einrichten einer Verbindung zur externen Benutzerverwaltung können Sie festlegen, nach welchen Regeln einzelnen Benutzern bestimmte xref:wato_user#contact_groups[Kontaktgruppen] oder xref:wato_user#roles[Rollen] zugewiesen werden sollen.
Dadurch können Sie beispielsweise die Berechtigungen für ganze Organisationseinheiten wie Standorte, Abteilungen oder Teams an nur einer Stelle zentral pflegen, statt für jede einzelne Person Einstellungen in {CMK} vornehmen zu müssen.
Sie können auch mehrere derartige Verbindungen konfigurieren, die dann gleichberechtigt nebeneinander existieren.


[#saml]
== Single Sign-On mit SAML

ifdef::onprem[]
{cee-only}
In den kommerziellen Editionen von {CMK} können Sie SAML-Dienste anbinden.
endif::[]
ifdef::saas[]
In {CE} können Sie SAML-Dienste anbinden.
endif::[]
SAML steht für  _Secure Assertion Markup Language_ und ist eine standardisierte Methode, externen Anwendungen und Diensten mitzuteilen, dass ein Benutzer derjenige ist, der er zu sein behauptet.
Durch SAML wird Single Sign-On (SSO) möglich, denn man kann damit einen Benutzer einmal authentifizieren und diese Authentifizierung dann an mehrere Anwendungen übermitteln.
Mit Hilfe der Verbindung und Kommunikation zwischen sogenanntem „Service Provider“ (SP) und sogenanntem „Identity Provider“ (IdP) wird es somit den Angehörigen einer Organisation ermöglicht, mit nur einer einzigen Anmeldung auf verschiedene Webanwendungen zuzugreifen.
In der SAML-Architektur stellt der Service Provider die Anwendung zur Verfügung und der Identity Provider verwaltet die digitalen Identitäten der Benutzer.

Für jede aktive SAML-Verbindung, die für eine Instanz verfügbar ist, erscheint im Anmeldedialog dieser Instanz ein Knopf zum Einloggen über die jeweilige SAML-Verbindung.
Beim Klick auf diesen Knopf erfolgt eine Umleitung zum angebundenen SAML-Dienst, der die dort verwalteten Zugangsdaten abfragt.
Ist das Login erfolgreich, informiert der SAML-Dienst die {CMK}-Instanz darüber.
Die nun authentifizierte Person ist ab jetzt eingeloggt und wird zur Startseite der {CMK}-Instanz weitergeleitet.

Falls diese Person vorher noch nie in dieser {CMK}-Umgebung eingeloggt war, wird hierbei automatisch ein entsprechender {CMK}-Benutzer für diese Instanz angelegt.
In der xref:wato_user#user_config[Benutzerübersicht] sind diejenigen Benutzer, die auf diese Weise angelegt wurden, sichtbar gekennzeichnet.
Bei ihnen erscheint in der Spalte [.guihint]#Connection# das Stichwort [.guihint]#SAML# zusammen mit dem Namen der zuständigen SAML-Verbindung.

// ES-todo: Screenshot aus der Benutzerliste einfügen
// ~/Documents/knw-2195-saml-ldap/screenshots/user_overview_from_different_connections.png

Typischerweise loggen Sie sich bei {CMK} aus, indem Sie in der Navigationsleiste unter [.guihint]#User# auf [.guihint]#Logout# klicken.
Beim Login über eine SAML-Verbindung genügt dies nicht.
Um die Sitzung sicher zu beenden, müssen Sie sich zusätzlich direkt beim jeweiligen SAML-Dienst ausloggen.

Wenn die Benutzer für Ihre {CMK}-Umgebung über SAML verwaltet werden sollen, übernimmt {CMK} die Rolle des Service Providers.
Als Identity Provider (IdP) stehen mehrere Möglichkeiten zur Verfügung.
Eine vollständige Liste der unterstützten SAML-Dienste finden Sie in der Übersicht über die Systemvoraussetzungen im Abschnitt xref:release_notes#saml[SAML IdP].

[TIP]
====
{CMK} implementiert die Benutzerverwaltung mit SAML basierend auf dem Standard SAML 2.0.
Jeder SAML-Dienst, der diesem Standard entspricht, kann grundsätzlich zur externen Benutzerverwaltung für {CMK} genutzt werden.
Die Liste der offiziell unterstützten Anbieter bezieht sich darauf, für welche Dienste Support von der {com} GmbH oder ihren Partnern angeboten wird.
====

Eine Anleitung zum Einrichten von SAML-Verbindungen in {CMK} finden Sie im Artikel xref:saml#[Anmeldung mit SAML].

[#ldap]
== Benutzerverwaltung mit LDAP/Active Directory
Die externe Benutzerverwaltung mit LDAP-Diensten steht in {RE} und den kommerziellen Editionen von {CMK} zur Verfügung.
Auch mit LDAP haben Sie die Möglichkeit, Benutzer und Berechtigungen an einer zentralen Stelle zu pflegen.

LDAP-Dienste folgen einem anderen Konzept als SAML-Dienste.
SAML-Dienste können Ihrer {CMK}-Instanz mitteilen, dass eine Person zum Zugriff auf diese Instanz authentifiziert ist.
Im Gegensatz dazu fragen LDAP-Dienste selbst keine Zugangsdaten ab.
Stattdessen werden sämtliche Benutzer, die dem LDAP-Dienst bekannt sind, regelmäßig mit der {CMK}-Umgebung synchronisiert.
Bei einer solchen Synchronisierung wird die Liste aller Benutzer für die jeweilige {CMK}-Instanz um diejenigen Benutzer erweitert, die durch die LDAP-Verbindung berechtigt sind.

// ES-todo: Screenshot der Benutzerliste einfügen mit LDAP-Benutzern

Im Anmeldedialog von {CMK} erscheinen LDAP-Verbindungen -- anders als SAML-Verbindungen -- nicht in Form von separaten Knöpfen für die Anmeldung.
Stattdessen können die Zugangsdaten eines Benutzers, der in einem angebundenen LDAP-Dienst bekannt ist, direkt als Benutzername und Passwort im {CMK}-Anmeldedialog eingegeben werden.
Zum Ausloggen genügt es, in der Seitenleiste unter [.guihint]#User# auf [.guihint]#Logout# zu klicken.

LDAP-Anbindungen können mit verschiedenen LDAP-Servern umgesetzt werden.
Eine vollständige Liste der unterstützten LDAP-Plattformen finden Sie in der Übersicht über die Systemvoraussetzungen im Abschnitt xref:release_notes#ldap[LDAP-Server].

Eine Anleitung zum Einrichten von LDAP-Verbindungen in {CMK} finden Sie im Artikel xref:ldap#[Benutzerverwaltung mit LDAP/Active Directory].

ifdef::onprem[]
[#user_unification]
== Zusammenführung von {CMK}-Benutzern aus SAML- und LDAP-Diensten
// Identity unification across SAML and LDAP (CMK-33805)

Benutzer, die über die globalen Einstellung einer Instanz angelegt wurden, und Benutzer, die aus externen Authentifizierungsdiensten entstanden sind, erscheinen in der Benutzerübersicht der Instanz unter [.guihint]#Setup > Users > User#.
Für jeden Benutzer ist vermerkt, welche Verbindung ihn erstellt hat.
Dabei wird der manuelle Weg als [.guihint]#htpasswd (htpasswd)# bezeichnet.

// ES-todo: Screenshot eines solchen Eintrags einfügen?

Die Spalte [.guihint]#ID# enthält eine innerhalb der eingerichteten Monitoring-Umgebung eindeutige ID.
Es kann vorkommen, dass eine Authentifizierungsverbindung versucht, einen Benutzer in einer Instanz anzulegen, dessen ID dort schon vergeben ist.
In den meisten Fällen führt dieser Versuch zu einem Fehler, weil die gewünschte ID bereits vorhanden ist.

{cce-only}
Falls Sie in den kommerziellen Editionen sowohl SAML-Verbindungen als auch LDAP-Verbindungen einrichten, können Benutzer mit identischer ID aus unterschiedlichen Quellen miteinander zusammengeführt werden.
Existiert beispielsweise ein Benutzer namens _hhirsch_, der über eine SAML-Verbindung angelegt wurde, so kann dieser Benutzer dennoch anschließend über eine LDAP-Verbindung synchronisiert werden.
Eine LDAP-Synchronisierung eines Benutzers mit der gleichen ID _hhirsch_ führt dazu, dass der zuvor existierende Benutzer _hhirsch_ ersetzt wird durch den gleichnamigen Benutzer aus dem LDAP-Dienst.
Rollen, Kontaktgruppen und weitere Attribute werden dabei aus LDAP übernommen.
Eventuell bereits gesetzte Werte für diese Attribute aus der SAML-Verbindung werden vollständig überschrieben.

Benutzerspezifische Einstellungen, Dashboards und Ansichten werden dabei übrigens nicht gelöscht.
Auch die Authentifizierung über die SAML-Verbindung ist weiterhin möglich.

Ab dem Zeitpunkt einer solchen Zusammenführung gilt die LDAP-Verbindung als Autorität über diesen Benutzer.
Die Zusammenführung funktioniert nur in dieser Richtung.
Wird der Benutzer _hhirsch_ zu Beginn von einer LDAP-Verbindung angelegt, kann der gleiche Benutzer sich zwar über eine SAML-Verbindung später ebenfalls einloggen, die Attribute werden aber weiterhin von der LDAP-Verbindung verwaltet.

Hinweise zum Löschen beziehungsweise Ausschließen von {CMK}-Benutzern aus verschiedenen Quellen finden Sie in den Artikeln über xref:saml#[SAML-] und xref:ldap#[LDAP-Verbindungen].
endif::[]
